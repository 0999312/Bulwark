## 1. 项目概述

| 项目 | 内容 |
|---|---|
| **游戏名** | 《前线壁垒》/ Frontline Bulwark（暂定）[P1] |
| **类型** | Top-down 俯视射击 · 生存挑战 · 基地防守 |
| **核心题材** | 士兵防守前线基地，迎战来自各方向的非人类怪物 |
| **核心循环** | 搜索 → 战斗 → 升级 → 构筑防线 → 更强敌人 |
| **关键特性** | 多武器切换、波次生存、升级/肉鸽成长、搜索-战斗循环 |
| **模式** | 单人 + 多人合作（2~4 人）同时设计 [已定 P2] |
| **引擎** | Godot 4.7 (mono)，GDScript 为主 |
| **平台** | 桌面端（Windows 优先）[P3] |
| **目标单局时长** | [P4]（建议 15~30 分钟一局，肉鸽化） |

### 一句话定位

> 一名士兵、一座前线基地、四面八方涌来的非人类怪物——在"出基地搜刮资源 → 回基地构筑防线 → 抵御波次进攻"的循环中活下来，用战利品把自己和防线武装到下一波。

### 核心体验（设计支柱）

1. **多方位压力管理**：怪物从不同方位袭来，玩家必须判断主压力方向、分配火力与防线资源。
2. **攻守转换的节奏**：防守波次（紧张）与出基地搜索（风险收益抉择）交替，形成呼吸感。
3. **构筑感与成长感**：局内通过升级选择构筑 build（武器+被动+技能），局外通过 meta 解锁成长。
4. **清晰可读的战斗**：俯视视角下弹道、敌群、基地状态一目了然，操作快速直接。

- **开发商**：Enkord（波兰小型开发团队）。

### 2.2 玩法特征总结

综合上述资料，Clash 'N Slash 的玩法特征可归纳为（细节以实际游戏为准）：

| 特征 | 说明 | 对本项目的参考价值 |
|---|---|---|
| **俯视视角生存射击** | 玩家控制角色在战场中移动射击，敌人持续涌来 | 基础视角与操作框架直接沿用 |
| **波次/关卡制推进** | PC 版共 16 关，关卡间有成长环节（B 站全流程视频可见） | 关卡结构与难度曲线参考 |
| **多方位来袭** | 敌人从战场各处出现，玩家需多向应对 | 与"多方位防守"设计支柱一致 |
| **武器系统** | 存在多种武器（fandom wiki 有 Default Cannon 等独立武器条目），武器可升级/更换 | 本项目武器切换与武器升级的参考 |
| **成长/升级经济** | 休闲平台游戏常见"战斗获得货币 → 关卡间购买/升级武器"结构（据评测与平台描述推断） | 局外成长（meta）与局内经济的参考 |
| **低成本高重复** | Flash 时代典型设计：单局时间短、可反复游玩 | 本项目肉鸽化单局设计的参考 |

### 2.3 借鉴与差异

- **借鉴**：俯视生存射击的操作手感、波次防守的压力节奏、武器多样性带来的构筑乐趣、关卡间成长循环。
- **差异（本项目的定位）**：
  - 题材从"太空/科幻"改为"**士兵 + 前线基地 + 非人类怪物**"（人 vs 怪物，而非飞船 vs 飞船）。
  - 引入 **基地防守系统**（基地本体有耐久、可构筑防线），而不只是角色自身生存。
  - 引入 **搜索-战斗循环**（主动出基地搜刮 vs 被动防守）——原版没有明确的"风险收益探索"结构。
  - 引入 **肉鸽局内成长**（商店随机刷新 + 固定物资，每局构筑不同），强化重复游玩价值。
  - 支持 **多人扩展**（原版为纯单机）。

> ⚠️ 注：Clash 'N Slash 部分细节（如具体武器列表、经济系统数值）来自公开资料的间接描述，后续如需精确复刻某机制，建议以实机游玩或视频逐帧确认。

## 3. 世界观与设定

### 3.1 背景（初稿）

> 前线战区的最后一道哨站。人类防线在"兽潮"（异变体集群）的冲击下节节后退，你被派到编号 [TBD] 的前线基地——至少任命文件上是这么写的。武器有限、补给靠搜刮、增援无期，每一波兽潮都在考验你的判断：**是留在墙内死守，还是冲出墙外抢回生存的物资？**

**世界观基调 [已定 P28 + P29]**：不追求宏大的末日解释——**怪物无论如何就是在那里**，来源不深究、不戏剧化。**主角表面是军人，但世界和人类文明已经荒诞地毁灭了，大概率不是什么正经军队出身**——军装是捡来的、编制是不知道谁给的、任务没有署名。因此整体风格**更随意、松弛、戏谑**：没有官僚腔的战地简报（只有不知谁留下的涂鸦式记录）、没有热血口号（只有"又来了？行吧。"）、没有英雄主义（只有"活着就行"）。叙事载体：随手写的便签、物品描述、基地日志——短、随意、荒诞（**不采用"恢复日常/重建家园"类主题**）。

### 3.2 关键词

- **士兵**：**表面军人** [已定 P29]——穿军装但不一定是正经军人（拾荒者 / 编外人员 / 前平民职业等，具体身份待定 [P29 细节]）；单人驻守或多人合作，装备可切换。
- **前线基地**：地图中心的枢纽，含基地本体（耐久核心）、可修复/可构筑的防线设施。
- **非人类怪物**：**异变体** [已定 P5]——基地周边异变而来的怪物集群；来源不做宏大解释 [已定 P28]，"它们就在那里"。

### 3.3 基调

- 紧张、硬朗的军事风格 × 怪物压迫感（参考：*They Are Billions* 的防守压力 + *Clash 'N Slash* 的爽快感 + 俯视肉鸽射击的手感）。
- 美术风格 [已定 P6]：**扁平矢量 + 描边卡通**混合——硬朗军事环境 × 卡通化异变体，形成高辨识度的"反差萌"风格（与项目 assets/theme 的 minimal_vector 契合）。
- 叙事基调 [已定 P28 + P29]：**非正经军人的随意荒诞感**——"怪物就在那里"，主角是穿军装的普通人，文本随意、松弛、戏谑（便签 / 涂鸦 / 冷幽默）；不采用"恢复日常/重建家园"类主题。

## 4. 核心玩法循环

### 4.1 宏观循环（一局的骨架）

```
出基地搜索（搜刮资源/弹药/建材/武器，有风险）
        ↓
回基地强化（升级武器/构筑防线/补给）
        ↓
防御波次（怪物从多方位来袭，守住基地）
        ↓
波间结算（基地商店：随机刷新商品 + 固定物资购买）
        ↓（循环，强度螺旋上升，数波后进入章节关底）
关底精英波（Boss 系统预留）→ 章节结算（meta 奖励 / 章节间选择）→ 下一章节
```

### 4.2 微观循环（单波节奏）

1. **预警**：广播提示下一波来袭方位与构成（"西北方向：虫群 3 组 + 喷吐者 1 组"）。
2. **部署**：玩家在窗口期布置/修复防线、调整站位。
3. **接敌**：怪物按路径冲向基地；玩家用主武器 + 切换副武器/技能迎击。
4. **扫尾**：清点残余，收集掉落（货币/材料）。
5. **结算**：波次奖励 + 基地商店（随机刷新商品 / 固定物资购买）。

### 4.3 节奏曲线（设计目标）

- 单局建议 15~30 分钟 [P4]。
- 前 1/4 为上手期（搜刮为主，波次温和）；中段进入攻守交替；后段压力陡增，逼迫玩家在"搜刮收益"与"回防时间"之间做取舍。
- 失败条件 [已定 P7]：**基地耐久归零即失败**；玩家阵亡可消耗资源复活（复活代价逐次递增），**资源不足以支付复活代价时失败**——"人活着基地没了"与"基地健在而人没了"都是困境。

## 5. 玩家角色与操作

### 5.1 角色

- 玩家扮演**"士兵"**（1 名；多人模式下每名玩家 1 名）——**表面军人、非正经军事人员** [已定 P29]：军装靠捡、任务靠听说、编制不存在，靠搜刮的装备和直觉活下去。
- 属性面板（初稿）：生命、护甲、移速、弹药容量、换弹速度、暴击率等——数值最终由升级系统驱动。
- 随身装备：**主武器 + 副武器 + 战术技能**（多武器切换是核心卖点之一）。

### 5.2 操作（键鼠为主，手柄适配 [P8]）

| 动作 | 键鼠 | 手柄 |
|---|---|---|
| 移动 | WASD | 左摇杆 |
| 瞄准/射击 | 鼠标（360° 自由瞄准） | 右摇杆（双摇杆模式） |
| 武器切换 | 数字键 1/2/3 或滚轮 | LB/RB 或按键循环 |
| 战术技能 | Q（或 E） | 肩键 |
| 互动（搜刮/修复/构筑） | E | 按键 |
| 冲刺/翻滚 | Shift | 左摇杆按下 |
| 地图 | Tab | 触控板/按键 |

- 瞄准策略 [已定 P9]：**鼠标纯自由瞄准**（无辅助）；**手柄提供轻辅助瞄准**（最近敌人微吸附），按输入设备自动区分。

## 6. 武器系统

### 6.1 设计原则

- **数据驱动**：每把武器是一个 Resource 配置（伤害、射速、弹速、散布、弹匣、换弹、特效、弹药类型）。
- **切换即策略**：武器切换没有冷却惩罚，但弹药独立，逼迫玩家规划弹药配比。
- **升级耦合**：武器既可局内升级（三选一强化卡），也可局外解锁/强化。

### 6.2 武器系统 v0.2：种类 → 具体枪械 两级设计 [已定 P10]

武器采用**两级结构**：

- **第 1 级 · 武器种类（8 类）**：决定手感 / 定位 / 弹药类型 / 弹道特征。
- **第 2 级 · 具体枪械（每类多个型号）**：同类下不同型号 = 数值微调（伤害 / 射速 / 弹匣 / 散布 / 独特词条），MVP 每类提供 **3 种**型号。

| 武器种类 | 定位 | 特征 | 弹药 |
|---|---|---|---|
| 突击步枪 | 万金油主力 | 中速连射、稳定 | 子弹 |
| 霰弹枪 | 近距爆发 | 扇形散射、近距离压制 | 子弹 |
| 狙击步枪 | 远程点杀 | 高伤、贯穿、慢速 | 子弹 |
| 轻机枪 | 压制 | 高射速、大弹匣、后座散布 | 子弹 |
| 火焰喷射器 | 范围持续 | 扇形持续灼烧、DOT | 燃料 |
| 榴弹发射器 | AOE 爆破 | 抛物线弹道、范围伤害 | 榴弹 |

**MVP 渐进路线** [已定 P10]：先开放 **3 类**（突击步枪 / 霰弹枪 / 手枪）× 每类 3 型号，后续解锁 **+2 类：轻机枪 + 能量步枪**（偏科幻手感，与虚构命名风格契合）；狙击步枪、火焰喷射器等其余类入扩展池。

**型号示例**（虚构命名 [已定 P26]，名单待定）：突击步枪类 = 高射速低散布型 / 高伤高后座型 / 三连发精确型（数值 + 每型号 1 个独特词条，如穿甲 / 燃烧弹 / 扩容弹匣）。命名风格示例："风暴-7 突击步枪""裂齿霰弹枪"。

> 第 2 级型号是主要扩展空间：未来可做"型号图鉴"，通过局内搜刮图纸 / 局外 meta 解锁。

### 6.3 武器切换规则 [已定 P11]

- **三槽位**：主武器 / 副武器 / 手枪，战斗中即时切换。
- **切换冷却（核心手感设计）**：
  - 主 ↔ 副：切换 CD **1.5s** [已定 P23]——换重武器是战术决策，不能无脑来回换；
  - 主/副 ↔ 手枪：切换 CD **0.3s** [已定 P23]——手枪是应急位（换弹被打断 / 弹药耗尽时的兜底）；
  - 手枪定位：**无限备弹、低伤害、快速拔枪** [已定 P25]，永远可用的最后防线，"过渡窗口"而非主力。
- 弹药按类型独立计数，搜索/掉落/补给点补充。
- 被动强化可包含"切换 CD 缩短"（例：主↔副 CD 缩短 50%），构成构筑方向之一 [P23]。
- 切换 CD 的具体数值、切换中是否可移动/可被伤害打断，待实机调参 [P23]。

## 8. 敌人设计

### 8.1 设计原则

- **多方位来袭**是核心支柱：刷怪点分布在地图四周（N/E/S/W + 斜向），波次构成决定压力方位。
- 敌人类型按"威胁模式"区分，而非单纯数值差异：
  - 近战冲锋（数量型）、远程威胁（点名型）、特殊威胁（机制型）、精英/Boss（压力峰值）。
- 所有敌人数据驱动（Resource 配置），便于扩展新类型。

### 8.2 敌人类型 v0.1（非人类怪物，初稿池）

| 敌人 | 威胁模式 | 特征 |
|---|---|---|
| 奔跑者 | 近战冲锋 | 高速直线冲向基地，数量多 |
| 自爆体 | 近战特攻 | 贴近后自爆，对基地和玩家都有威胁 |
| 装甲兽 | 近战重装 | 高血量、破防需特定武器/部位 |
| 喷吐者 | 远程弹幕 | 中距离喷射弹体，逼玩家走位 |
| 狙击手怪 | 远程点名 | 蓄力射击，高伤单体 |
| 飞行体 | 空中绕后 | 无视路障，专打防线后侧 |
| 潜伏者 | 隐匿突袭 | 潜行至近处现身，逼玩家保持警戒 |
| 精英·巨兽 | 波次核心 | 高血高伤，带小怪光环 |
| Boss·巢穴母体（预留）[P14] | 后续章节终点 | 持续召唤小怪，需要拆解机制（当前由精英波代替） |

**部位 / 弱点设计（裁剪结论）[已定 P31]**：

- **全身部位系统（肢体独立血量/破坏）：不采用**——2D 俯视下部位可读性差，部件化渲染与命中细分成本高，与本作大量敌人快节奏玩法冲突。
- **弱点机制（Weak Point）：采用，限定大型目标**（精英·巨兽、未来 Boss），2D 射击常态设计：
  - **形态**：发光核心 / 头部 / 背部（朝向判定：巨兽转身露出背部弱点）；
  - **效果**：伤害倍率（建议 2.0×，待调）、命中硬直（打断蓄力攻击）、破甲（移除减伤）；
  - **联动**：狙击步枪（点杀定位）、标记射击（暴露 / 增幅弱点）、鼠标精确瞄准占优（手柄轻辅助不吸附弱点）；
  - **表现**：弱点发光 / 描边醒目 + 独立受击反馈。
- **方向性护甲（简化部位）**：装甲兽正面减伤、侧 / 背无减伤——2 态朝向判定，不做独立部位。
- **普通小怪：单一受击盒**，不做部位。

### 8.3 波次系统（初稿）

- 波次由 **构成（敌人组合）+ 方位（来袭方向）+ 强度（数量/等级）** 三元组生成（可程序化生成，见 §14 PCG 预留）。
- 波间窗口期：搜刮 + 构筑 + 修复。
- **章节节奏 [已定 P21]**：每章 **3~4 波**，章末关底（当前为**精英波次** [已定 P14]，Boss 系统预留扩展位）。
- **关底精英波**：由精英（§8.2 精英·巨兽）+ 强化小怪构成，承担章节压力峰值；后续版本可替换为机制型 Boss（弱点 / 阶段 / 召唤），架构按"可替换关底实体"预留。
- 难度曲线：人口压力（同屏数）与质量压力（敌人等级）交替上升。

## 9. 基地与防线

### 9.1 基地本体

- 位于地图中心的固定据点，有**耐久值（核心生命）**。
- 怪物攻击基地时优先攻击防线设施，突破后直接啃基地本体。
- 基地耐久归零 → **失败** [已定 P7]。
- **玩家复活点** [已定 P7 + P20]：玩家阵亡后在基地复活，消耗**专用复活资源**（暂名：应急储备，命名待定）。
  - 复活资源的**初始数值**由开局情况决定（局外养成加成 + 章节要求基础值）；
  - **局内极难补充**（仅极稀有事件 / 搜索点可微量获得）——复活次数本质有限；
  - 该资源不足以支付复活时，阵亡即失败。

### 9.2 防线管理

- 玩家在波间/战斗中消耗资源（建材/能量/弹药）部署设施（§7.3）。
- 设施可被破坏，需要修理或重建（消耗资源）。
- 防线的作用：拖延与转化压力（路障拖延、炮塔转化火力），**不能完全替代玩家**——设施有弹药/耐久上限。

### 9.3 资源系统（初稿）

| 资源 | 来源 | 用途 |
|---|---|---|
| 建材 | 搜索搜刮、波次奖励 | 构筑/修复防线 |
| 弹药 | 搜索、补给点、掉落 | 武器射击 |
| 能量 | 波次奖励、发电机设施 | 设施运转/特殊功能 |
| 货币（局外） | 每局结算 | meta 解锁（见 §10.3） |
| 应急储备（复活资源） | 开局配置（meta + 章节基础值） | 玩家复活；局内极难补充 [已定 P20] |

## 10. 升级 / 肉鸽系统

### 10.1 局内成长（基地商店制）[已定 P15]

- 每波 / 每章节结算后进入**基地商店**：以战斗与搜索获得的**货币**购买升级。
- **随机刷新区** [已定 P22]：每波结算刷新 **4 个**随机商品（稀有度：普通 / 稀有 / 史诗 / 传说），价格随稀有度与购买次数递增（同商品重复购买 +30% 级）。
- **固定物资区**：满足特定条件后稳定上架的商品（进度解锁 / 搜索到关键物品 / 防守成就），保证每个构筑方向都有可控的主线升级路径。
- 构筑方向：武器特化 / 生存续航 / 防线强化 / 战术循环 / 资源经济——玩家用资源选择权自主混合。

### 10.2 局内经济与风险收益

- 波间窗口期可**出基地搜索**：地图上分布着搜刮点（补给箱/残骸/坠毁运输车），开启可获得资源或武器，但可能触发遭遇战，且占用回防时间。
- 核心张力：**搜刮收益 vs 回防时间**——波次倒计时不会等人。

### 10.3 局外成长（Meta）[已定 P16：有]

- 每局结算获得货币，用于永久解锁：**新武器种类/型号、新战术技能、新敌人难度层、角色外观、起始装备**。
- 目标：让"输了也有成长"成立，支撑重复游玩。
- meta 解锁节奏：保证"每 1~2 局必有新内容可解锁"，与章节制单局（20~30 分钟）匹配。

## 13. 多人扩展设计

### 13.1 目标形态 [已定 P2：单人与多人同时设计]

- **设计基准**：单人（1 名士兵守基地）与多人合作（2~4 名士兵共同守一座基地，共享基地耐久与资源池，独立武器 / 构筑 / 经济）**从策划与架构第一天同时设计**，避免"先单人后补多人"的返工。
- 多人数值按人数缩放（波次构成、敌人血量 / 数量、商店价格）。
- **无 PvP（明确非目标）** [已定 P30]：本作仅合作防守，不包含任何玩家对抗模式，架构不为 PvP 预留。
- **队友伤害（Team Kill）：禁止** [已定 P30]：友军伤害完全关闭——玩家对玩家伤害为 0，AOE（手雷 / 空袭 / 霰弹散射）与附带效果（灼烧 / 标记）均排除友军。理由：
  1. **玩法**：合作防守下友军火力密集，误伤将高频发生，惩罚机制只会变相惩罚队友，不友好；
  2. **世界观**：在"非正经军人同守一座基地、怪物就在那里"的基调下，允许甚至鼓励玩家互害是别扭且可耻的设计。

### 13.2 多人架构预留（从第一天起不堵死）

- **权威模型**：采用"**服务器权威 + 客户端预测/插值**"（参考 game-architect multiplayer 参考）——战斗伤害、资源、基地耐久、敌人 AI 由权威端裁决；客户端负责输入与表现。
- **单机即服务器**：Godot 的 ENet 多层架构天然支持"主机即服务器"（host-authority），单机模式 = 本机服务器 + 本机客户端，代码路径与多人一致。
- **同步风格**：世界状态用状态同步（snapshot/delta）；玩家移动用预测+校正；meta/商店用请求-响应。
- **代码约束**（架构硬性要求）：
  - 战斗结算、经济、基地耐久等**核心规则**必须走统一接口（本地与远程无分支差异）；
  - 敌人 AI、波次调度由权威端驱动；
  - 武器/敌人/升级数据全部数据驱动 → 天然可同步与扩展。

### 13.3 合作模式要点（初稿）

- 波次强度按玩家人数缩放（人口曲线调整）。
- 职责分工自然涌现：1 人前出搜刮、1 人留守修防线。
- 共享资源池 + 独立构筑：需要讨论"资源归属"规则 [P19]（各捡各的 vs 进公共池）。

### 14.1 模块划分（对应 §1 项目概况的目录约定）

### 14.2 关键系统与选型

| 系统 | 方案 | 备注 |
|---|---|---|
| 事件通信 | mc_game_framework EventBus | 解耦战斗/UI/音频 |

### 14.3 可扩展性设计要点

> **Mod 前置（v1.0 补充，M0 起硬性生效）**：所有内容统一经 MSF 注册表以 `ResourceLocation(namespace:id)` 注册（官方 `bulwark:` 命名空间，Mod 用各自 mod_id），与 Minecraft Mod 生态同构——**Mod 即"注册更多条目"**；**Mod 按作用端分层**：gameplay Mod（影响逻辑/权威内容）多人下**双端强一致**（清单 + 内容哈希，不一致拒绝加入）；client-only Mod（资源更换 / UI 美化 / 画面光影优化）**允许单端、不参与校验**（单端模组是生态正常形态）；**前后端分离为硬性原则**（渲染与逻辑解耦，后端纯逻辑可 headless 运行）。详见架构文档 §10。

1. **数据驱动优先**：所有内容（武器/敌人/升级/波次/设施）= Resource，新增内容零代码。
2. **核心规则与表现分离**：战斗/经济/耐久逻辑不依赖表现节点 → 单人/多人共用，且可被 GUT 单测（项目已装 gut）。
3. **PCG 预留**：波次构成用"种子 + 生成规则"（构造法），未来可无缝切换为在线生成或 AI Director 动态调压。
4. **技能系统按"可裁剪"设计**：Framework（施法流程）+ 可复用 Action 原子（生成弹道/施加伤害/上状态），技能集增减只增删数据与少量 Action。
5. **测试友好**：逻辑层可 headless 运行，GUT 覆盖波次生成、伤害公式、经济结算。
6. **Mod 预留**：数据类 Mod 零代码扩展（注册条目：新武器/敌人/商品…）；代码类 Mod 注册脚本类扩展（新 Action/弹道模式/敌人行为）；加载管线复用 GodotModLoader（CC0，参考 `new_project/addons/mod_loader`）；**gameplay Mod 双端强一致、client-only Mod 允许单端**（manifest `side` 声明，详见架构文档 §10.6）。

## 16. 技能集裁剪流程

> 目标：从 §7 的完整初稿池，裁剪出 MVP 技能集。裁剪在每个 [P#] 确定后迭代执行。

### 16.1 裁剪评分（初稿标准）

对每个技能/武器/敌人/设施计算：

```
保留分 = 核心循环关联度 × 0.5 + 可组合性(构筑深度) × 0.3 + 实现成本(低=高分) × 0.2
```

- 评分 < 阈值 → 降级为"扩展内容"（局外解锁或后续版本）。
- 同定位冲突 → 保留体验差异最大的（如"手雷 vs 榴弹发射器"只留其一或差异化）。

### 16.2 裁剪步骤

1. **定骨架**：确定核心循环（§4）与失败条件（P7）→ 推导出"必须有"的最小功能集。
2. **定 MVP 集**：按评分裁剪武器（P10）、战术技能（P12）、被动池（P13）、敌人（保留每威胁模式 1 种）、设施（保留 3 种）。
3. **定扩展层**：被裁掉的进入"扩展池"，作为后续迭代/局外解锁内容。
4. **验证**：每个裁剪版本用 GUT + 可玩性检查（完成率、死亡位置）回归。
